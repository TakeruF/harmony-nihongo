# かな入力の実装と検証

2026-10-07、Pura 70（ADY-AL10）/ HarmonyOS `7.0.0.109(SP6C00E105R5P2)`、API 26。アプリ0.2.0 / versionCode 100001。署名済みデバッグHAPで検証。

## 実装

- Gboard参考の5列×4段のかなキー。中央/左/上/右/下のフリック、や行・わ行・句読点の個別テーブル。
- 指IDごとの追跡、12vpの判定距離、タッチ取消。離脱順が逆でも押下順に出力し、入力先セッションが変わった指の結果を破棄。
- `KanaComposition`にかな列とカーソルを保持。濁点・半濁点・小文字、削除、左右移動、取消、かな確定。
- 動画を参考に「゛゜小」キーへ修飾を集約。例：`は→ば→ぱ→は`、`つ→っ→づ→つ`。
- 入力中は横一列の候補帯のみを表示。モード切り替えを上下に重ねない。動画の720px幅に対して約104pxの候補帯と、画像の940px幅に対して136pxのツールバーは同じ比率。`KeyboardMetrics.toolbarHeight`を共有し、キー領域を動かさない。
- 現在の候補帯には実際の未確定かなを表示し、タップでかな確定。漢字候補と候補展開はMozc接続後に追加する。
- 設定はアプリ内の独立したページ。[設定共有の前提・申請文案](settings-sharing.md)。承認前の設定変更は無効。

プレビューは公式APIの`setPreviewText(..., {start:-1,end:-1})`で全置換し、確定は`finishTextPreview()`のみを使う。エラー12800011のときはIME内の未確定表示へ切り替え、確定時にだけ`insertText()`を送る。固定値のEnterを使わず入力先の`enterKeyType`へ従う。[Huawei公式・プレビュー](https://developer.huawei.com/consumer/cn/doc/doccenter-dev-faq/faqs-ime-7)

## 検証した範囲

| 層 | 結果 |
| --- | --- |
| ArkTS/CMake | ビルド成功 |
| 署名・配備 | 最終HAPの公式hap-sign-tool検証（SHA-256、verify-app）成功。実機へインストール済み |
| 純粋な入力ロジック | 本番モジュールをSDKのTypeScriptで変換して実行。かな編集、修飾、5方向、取消、2指の逆順離脱、100指の逆順離脱、連続タップの700ms境界、設定の排他・不正値の拒否が成功 |
| 実機プレビュー | `きょうは`、`がっこう`、`ぴゅっと`をフリックし、表示と一度だけの確定が成功 |
| 未確定編集 | `きょうは`の途中へ移動し削除→`きょは`、途中挿入→`きょうは`、取消→空文字が成功 |
| 非対応入力欄 | テスト画面のTextInputでプレビューを無効化。入力中は空欄、確定後のみ`きょうは`、次のEnterで検索が成功 |
| 入力欄切替 | 非対応入力欄の未確定かなが次の欄へ混ざらない |
| 高速処理 | 一時QAタイマーから本番のかな入力・プレビュー経路へ10ms間隔で80文字を投入。`あいうえお`×16が順序どおり反映。QAタイマーは最終ソース/HAPから除去 |
| 最終候補帯 | 横一列への変更後に`きょうは`のプレビューと一度だけの確定を再確認 |

高速試験は実際のInputClient・プレビューAPIを使うが、人が毎秒100回フリックした証拠ではない。実機の2指同時注入は行っておらず、逆順離脱は本番ロジックのホストテストで確認。

アプリ内の設定ページの表示と、未承認時に4つの変更トグルが無効になっていることを実機UIツリーで確認。

AGC共有領域が未承認のため、設定値の主アプリ→IMEへの反映、ケータイ設定の実機利用は未完了。独立したSettingsValuesと連続タップのロジックはホストテストで検証済み。漢字変換、Web入力欄、横画面、タブレット、日本語QWERTYは次段階。

```sh
node tools/test-kana.cjs
python3 tools/build.py
python3 tools/test-kana-device.py
```

実機スクリプトはPura 70の縦画面、標準設定、Harmony Nihongoの選択を前提とし、自作アプリのテスト欄をリセットする。証拠は`artifacts/phase1/kana-results.json`、`burst.json`、`final-checks/`と実機画面。最終HAPは`artifacts/phase1/HarmonyNihongo-0.2.0-debug.hap`。
