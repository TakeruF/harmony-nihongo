# 外部アプリの入力互換性

以下は0.12.0時点の記録。0.12.1ではChatGPTの変換前表示と未変換送信を追加修正した。[最新の動作と試験](chatgpt-live-composition-2026-10-08.md)を参照。

## ChatGPTで再現した問題

Pura 70（ADY-AL10、7.0.0.109/SP6C00E105R5P2）の完全アクセスモードで、出境易1.02.50内のChatGPTを検証した。Android版ChatGPTのバージョン番号は取得していない。

修正前は、フリック入力の最初の「き」だけが候補帯に残り、入力欄には表示されず、後続の操作が進まなかった。プレビュー対応フラグはtrueだったが、`getTextIndexAtCursor()`が完了しなかった。さらに、非同期の`insertText()`で文字が実際に入っても完了通知が戻らず、次の削除が待たされた。

## 入力処理

- 編集先への接続時に、副作用のないカーソル位置の読み取りを試す。400ms以内に返答がない場合は、プレビューを使わず、かな・変換候補をキーボード内に保持する。
- この互換処理では、確定・英字・数字・貼り付け・削除・カーソル移動を、入力キューの順番で一度だけ渡す。完了通知を待ち続けたり、返答のない書き込みを再送したりしない。同期APIも使わず、IMEのUIスレッドを待たせない。
- 編集先が返す`isTextPreviewSupported=false`も尊重する。通常のHarmonyOS入力欄では、従来のプレビューと完了通知の確認を維持する。
- 編集先の変更時にキューを更新し、古いカーソル読み取りが後から完了しても新しい入力欄へのプレビューを書き込まない。古い編集先の失敗通知も新しい編集先に表示しない。
- 互換処理では、完了通知を得られない変換を学習せず、選択文字の再変換を提供しない。改行は文字として挿入する。検索・送信などのアクションはアプリに一度だけ渡すが、今回のChatGPT試験ではメッセージを送信していない。

操作を渡せたという内部ログだけで、入力が完了したとは扱わない。実際の外部入力欄のテキストとスクリーンショットで確認する。

## 試験方法

`tools/test-external-editor-device.py`は、開かれている空の入力欄を対象とする。既存の非空の下書きは変更せず、試験用の文字だけを入力・削除する。かな読み、Mozc候補の確定、削除、英字・数字とモード切替を確認する。通常の試験では、かな確定、途中挿入、カーソル長押し、改行、絵文字と削除も確認する。

Web入力は`tools/fixtures/external-editor.html`を一時HTTPサーバーで表示する。ネイティブのブラウザーはHDCの逆転送、出境易のChromeはMacのLANアドレスを使う。単行・複数行・contenteditable・パスワードを分ける。contenteditableの空のキャレット段落をArkWebが`\\n`としてアクセシビリティに出す場合は、ページが表示する実DOMの値でも確認する。この端末のブラウザーではパスワード欄を選ぶとシステムの安全キーボードに切り替わることを目視確認した。これをHarmony Nihongoでのパスワード入力成功とは扱わない。実際のパスワードは入力していない。

ホストでは、カーソルの無応答、遅れて届く返答、編集先の変更、書き込み・削除の完了通知がない場合、重複送信の防止、失敗通知の扱いを確認する。

実機の各結果・画像は`artifacts/external-editors/`、ホスト結果は`artifacts/gboard-polish/host-tests.txt`に保存する。対象を確認していないアプリ・OS・基本アクセスモードまで対応済みとは扱わない。
