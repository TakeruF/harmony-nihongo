# MVP実装計画

前提と公式資料は[技術調査](feasibility-2026-10-07.md)を参照。検証対象は実機で確認したPura 70（ADY-AL10）/ HarmonyOS `7.0.0.109(SP6C00E105R5P2)`、API 26、arm64-v8a。手元のSDKは`26.0.0.23 Beta1`。

## 構成

```text
Settings UIAbility
  └─ 有効化の案内・設定・OSS通知

InputMethodExtensionAbility（独立プロセス）
  ├─ ArkUI: かなキー・未確定文字・候補バー
  ├─ Input Controller: フリック・かな列・状態遷移
  ├─ Editor Adapter: InputClient・プレビュー・確定
  └─ Node-API → C++ Mozc Adapter → Mozc Engine/SessionHandler
       ├─ 同梱OSS辞書
       └─ IME独立サンドボックスの学習データ
```

3層構成を維持しつつ、OSとの接続をEditor Adapterに閉じ込める。設定アプリとのプロセス・保存先境界も明示する。

段階0は実機で完了。[検証記録](phase0-validation-2026-10-07.md)に結果とGboard参考寸法を記載。かな入力の基本経路も実機検証済み。[段階1の検証](phase1-validation-2026-10-07.md)を参照。アプリ設定の共有はAGC承認待ち。Mozc接続は未実装。

## かな入力と状態

`あ か さ / た な は / ま や ら / わ`は10グループ。一般的な12キー配置として記号・変換・削除などを周囲に置く。名称の「9キー」と実際のキー数を混同しない。

- 中央タップ/左/上/右/下は原則あ/い/う/え/お。や行・わ行は個別テーブルで定義。
- 濁点・半濁点・小文字は変換可能な文字にのみ適用。
- フリック距離はvp基準で調整し、タッチ取消、指がキー外へ動くケース、マルチタッチを定義。
- ケータイ式連打は後の独立した入力方式とし、初期のタップは行の先頭かなを一度入力。
- Unicodeの扱いを明示し、濁点を結合文字のまま保持するか正規化するか統一。

Controllerの正本は`reading`、未確定部分のカーソル、`Idle/Composing/Converting`、候補世代、入力先セッション世代。確定済み文章は入力先アプリが保持する。

Backspaceは未確定文字があれば内部編集、なければ入力先へ前方削除。変換中はかな編集への復帰を先に行う。入力欄のタップ・選択変更・フォーカス喪失は状態を同期し、別の入力欄へ未確定文字を送らない。

## 変換ラッパーの案

以下は製品側APIの設計案であり、Mozcが直接提供する関数名ではない。

```text
initialize(dictionaryPath, profilePath)
startSession() -> sessionHandle
setComposition(sessionHandle, reading, cursor, revision) -> EngineState
convert(sessionHandle, revision) -> EngineState
chooseCandidate(sessionHandle, candidateId, revision) -> EngineState
commit(sessionHandle, revision) -> CommitResult
cancelConversion(sessionHandle) -> EngineState
reset(sessionHandle)
endSession(sessionHandle)
```

`EngineState`に未確定表示、文節、候補ID、表示文字列、対象となる読みの範囲を含める。表示インデックスをMozc候補IDとして送らない。文節候補・部分確定を「全文候補」と誤って扱わない。

同一セッションへの呼び出しは直列化し、結果にrevisionと入力先の世代を付ける。UIは古い結果を捨て、セッション破棄後のコールバックを無視する。確定失敗時に読む文字を失わない設計を検証する。

`UPDATE_COMPOSITION`を使った全置換方式はMVP候補。カーソル・Undo・予測・学習への影響を検証し、必要なら増分キーイベント方式へ変える。UIはその違いを意識しない。

## 実機の受け入れ項目

初回に端末機種、OSビルド、API、SDK、アプリSHA、Mozc SHA、辞書バージョン、安全モードを記録する。ログには入力文字や個人の文章を記録せず、テスト用定型文で検証する。

- システム設定にIMEが表示され、選択できる。
- 自作テスト画面だけでなく、他アプリの入力欄で動く。
- かな入力→実際のMozc候補→候補確定が一度だけ反映される。
- かなだけの確定、変換取消、未確定削除、確定済み文字の削除。
- プレビュー対応・非対応、単行・複数行、Web入力欄。
- 検索/送信/改行のEnter。候補確定で送信まで実行しない。
- 英数字/数字/パスワード等の入力属性に応じた挙動。安全な入力欄でのシステムIMEへの切替も記録する。
- 入力欄A→B、アプリA→B、IME切替、画面回転、サービスの再作成。
- 素早い入力・削除・候補タップで古い候補を誤確定しない。
- 基礎モードでNative呼び出し・同梱辞書・必要なファイル操作が成立する。
- 辞書欠損/読み込み失敗時はかな入力へ戻り、IME全体が落ちない。
- 初回表示、温まった状態の表示、変換の所要時間とメモリを測定してから性能目標を決める。

現時点のMVP範囲はフリック、日本語変換、候補確定、削除、かな/数字/英字切替。文節の手動調整、再変換、学習管理、音声、クリップボード、他言語エンジンはその後に追加する。
