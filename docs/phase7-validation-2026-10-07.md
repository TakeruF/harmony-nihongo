# 日本語QWERTY（0.8.0 / versionCode 100007）

「あa1」の長押しで12キーと日本語QWERTYを切り替える。短押しは日本語→英字→数字→選択中の日本語レイアウト。「日本語」スペースキーは未確定文字がある場合に文節変換、ない場合にスペース。候補タップで全文確定、文節変換時は候補選択後に右下のEnterで全文確定する。文節変換中の左右キーは短押しで文節移動、長押しで区切りを調整する。

`RomajiInput.ets`は未完成のローマ字を保持し、母音、清音・濁音・半濁音、拗音、促音、小書きかな、基本的な外来音を逐次かなへ変換する。`ky`はそのまま表示し、`o`で`きょ`になる。`n`は確定・変換・カーソル移動の際に`ん`になり、`nn`は`ん`を二重に確定しない。`nna`、`nnya`にも対応する。未完成部分のBackspaceはローマ字を1文字削除し、変換済み部分はかなを1文字削除する。未完成の`k`などを確定する場合は文字を保持する。独自の基本テーブルであり、Mozcの全ローマ字規則やカスタムテーブルを再現したものではない。

`ImeController`はローマ字も既存の世代付き編集キューで処理する。未完成のローマ字を含む間はMozcに候補問い合わせを送らず、解決した読みを既存の変換・学習・文節処理へ渡す。候補の世代チェック、プレビュー非対応欄のローカル保持、確定時の一度だけの挿入を共有する。フリック入力へ切り替える際は未完成部分を確定する。

UIは既存のGboard参考`KeyboardMetrics`のQWERTY幅・高さ・縦横間隔をそのまま使用。英字と日本語のQWERTYは別の描画分岐で構築し、切り替え時にスペースのラベルと操作が一致するよう更新する。横一列の候補バーと展開候補も既存部品を使用する。モード選択の追加行は設けていない。アプリ設定画面には長押し操作の説明を表示する。共有領域は未取得のままで、設定画面からのレイアウト選択・永続化はまだ有効にしていない。IME再起動時は12キーへ戻る。

- `node tools/test-conversion-controller.cjs`: 120文字のローマ字を待たずに投入して80文字のかなへ変換、候補確定、未完成nの確定、カーソル途中挿入、フリックへの切り替え、プレビュー非対応、文節変換。従来の高速かな・古い候補・文節伸縮・再変換の回帰ケースも通過。
- `node tools/test-kana.cjs`、`node tools/test-cursor-hold.cjs`、`node tools/test-haptics.cjs`: 通過。
- `python3 tools/build.py`: SDK26のArkTS・C++・デバッグ署名ビルド成功。今回の変更でMozc本体とネイティブAPIは変更していない。

## 実機検証

Pura 70 / HarmonyOS 7.0.0.109、API26、FULL_EXPERIENCE_MODE。自アプリのTextAreaとプレビュー非対応TextInputを使用。第三者アプリや基礎モードでの今回のQWERTY検証は行っていない。

`python3 tools/test-romaji-device.py`で長押し切り替え、ローマ字プレビュー、Mozc候補タップ、未完成文字削除、n/nn確定、連続入力、文節変換、非対応欄の確定・検索未送信、フリックへ戻った後の入力、英字・数字との切り替えを検証する。既存の学習データを削除せず、文節候補は明示的に選択する。実行結果は`artifacts/phase7/device-results.json`、UIは`qwerty-candidates.png`と`qwerty-ime.png`、`qwerty-segments.png`に保存。

連続入力は72回の実タッチで`gakkou`を12回入力。計測値は`typing-timing.json`に保存する。ホストで120文字を待たずに投入する試験と、実機の約5〜6キー/秒の試験は別の検証であり、実機でそれ以上の速度を保証するものではない。
