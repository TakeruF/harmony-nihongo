# ChatGPTでの変換前表示とアプリ送信

## 変更した動作

ユーザー提供のGboard動画を参照し、出境易内ChatGPTで未確定のかなが入力欄に下線付きで表示されるようにした。候補を選ぶとそのプレビューを変換文字に置き換えて確定する。変換前にアプリの送信ボタンを押すと、表示中のひらがなが送信される。

0.12.0の互換処理では、カーソル読み取りが400msで完了しないとプレビューまで無効化し、かなをキーボード内部だけに保持していた。これは入力停止を回避するが、今回の期待を満たさなかった。

0.12.1では読み取りの無応答とプレビュー非対応を区別する。読み取りが無応答でも、プレビュー対応の入力欄には既定範囲（start/end=-1）でsetPreviewTextを一度だけ渡す。返答がない場合もキューを止めず、確定時も同じ範囲を更新してfinishTextPreviewを一度だけ渡す。書き込みを再送せず、同期APIも使用しない。非対応を明示する入力欄のローカル保持は維持する。

互換環境では確実な絶対アンカーを取得できないため、その編集先の選択通知を通常エディターの絶対範囲判定に使わない。入力欄が空になった通知や接続終了で未確定状態を破棄し、新しい入力に持ち越さない。通知が来ない編集先での操作受理は内部状態だけから保証せず、実機の入力欄で確認する。

## 確認結果

Pura 70 / HarmonyOS 7.0.0.109、完全アクセスモード、出境易1.02.50内のChatGPTで確認。

- 通常・連続入力の20項目PASS。変換前「きょうは」が実際の入力欄にあること、候補確定、削除、英字60回・かな10回の連続入力、途中挿入、カーソル長押し、改行、絵文字を確認。
- 0.12.1をインストールし、未変換「あか」をアプリの送信ボタンで1件送信。送信されたメッセージが「あか」であることを確認。
- 送信後の入力は「さ」だけになり、前の読みが戻らないことを確認。試験用の下書きは削除。
- 0.12.1でネイティブ入力欄のかな回帰試験15項目PASS。プレビュー、確定、取消、途中挿入、非対応欄のローカル保持、入力欄切替を確認。
- ホスト9スイートPASS。返答のないプレビュー更新・確定、二重挿入防止、削除・取消、アプリによる欄の消去後の新しい読みも試験。

20項目の試験は最終ソースを含む0.12.0で行い、その後にバージョン情報だけを0.12.1へ更新してビルド・インストールし、送信の3項目を確認した。他の外部アプリ全件を0.12.1で再試験したとは扱わない。
